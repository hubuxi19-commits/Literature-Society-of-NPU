# 西北工业大学学生文学社作品交流平台设计规格

## 1. 产品定位

本项目是一个持续更新作品、持续产生评论与回复的高校文学社交平台，不是按刊期发布的电子刊物。视觉借用现代中文文学出版物的克制、留白和排版秩序，但内容组织遵循长期运行的社区产品逻辑。

主要用户是文学社成员、普通读者和编辑管理员。首页的首要任务是让读者快速发现新作与活跃讨论，并自然进入安静、舒适的长文阅读环境。

明确不采用：

- 季刊、刊期、本期主题、封面作品等周期出版结构。
- 校园门户、航空航天、西工大深蓝等视觉符号。
- 玻璃拟态、大面积渐变、表情符号导航和圆角卡片瀑布流。
- 首页展开作品全文。
- 长期占据侧栏的登录、注册或投稿表单。
- 任何公开展示学号的界面。

## 2. 视觉系统

### 2.1 色彩

- 纸白 `#F3EEE3`：页面主背景。
- 浅纸 `#FBF8F1`：阅读正文和弹层背景。
- 正文墨 `#1D1B18`：标题与正文。
- 浅墨 `#696158`：元信息、说明与次要控件。
- 朱砂 `#8C2F2B`：重点操作、选中态、编辑标记。
- 细线 `#CFC4B3`：分区、列表和输入框边界。

### 2.2 字体

- 标题：`Songti SC`, `STSong`, `SimSun`, `Noto Serif CJK SC`, serif。
- 正文：`Noto Serif SC`, `Source Han Serif SC`, `Songti SC`, serif。
- 元信息：`FangSong`, `STFangsong`, `PingFang SC`, sans-serif。

使用系统字体优先的字体栈，不依赖 GitHub Pages 在中国大陆可能加载不稳定的在线字体。

### 2.3 布局与标志性元素

页面采用宽松的编辑目录式布局，作品之间以细线分隔，不将每一项包装成浮起的卡片。桌面端主内容与社区侧栏约为 2:1，移动端合并为单列。

唯一强调性的视觉元素是“朱批式边注”：分类、编辑推荐与互动状态在作品条目边缘以小号朱砂文字呈现。它既承载真实信息，也形成文学社平台的辨识度。除该元素外，装饰保持克制。

动效仅用于视图淡入、弹窗、抽屉与阅读进度，持续时间为 120–220 毫秒，并遵守 `prefers-reduced-motion`。

## 3. 信息架构

应用为适配 GitHub Pages 的原生 JavaScript 单页应用，使用哈希路由：

- `#/`：首页与持续更新的新作流。
- `#/works/:id`：独立作品阅读页。
- `#/write`：独立写作台。
- `#/authors/:id`：作者主页。
- `#/discussions`：活跃讨论聚合页。
- `#/submissions`：征稿启事与社区规则。

首页依次包含：

1. 刊头式站点导航，但不出现刊期或封面语义。
2. 社区题记与编辑部短消息。
3. 编辑推荐和正在讨论。
4. 分类、排序与关键词搜索。
5. 持续更新的新作流。
6. 热门作者、热门作品和征稿提示。
7. 社区规则、项目说明和联系信息。

## 4. 页面与交互

### 4.1 刊头导航

显示文学社名称、首页、新作、讨论、社员、征稿入口，以及搜索、写作和账户操作。移动端折叠为可访问的菜单，保留显眼的“开始写作”入口。

### 4.2 首页

首页不展示全文。每条作品显示标题、笔名、分类、发布时间、两至三行摘要、点赞数和评论数。编辑推荐以置顶目录形式呈现，正在讨论区域展示作品标题、评论者笔名和最新评论摘要。

搜索同时匹配标题、摘要和笔名。分类包含诗歌、散文、小说、随笔和其他。排序支持最新发布、最多喜欢和最多讨论。

### 4.3 阅读页

正文区域限制在适合中文长文阅读的宽度，使用较大行高、明确段落间距和稳定的字距。页面显示标题、作者笔名、分类、发布时间和阅读进度，不显示学号。

正文之后依次为点赞操作、作者简介、评论输入、评论树和相关作品。删除作品入口只对作者本人和管理员显示，并在执行前二次确认。

### 4.4 登录与注册

登录和注册使用可关闭的模态弹窗。用户界面只要求学号、密码和笔名。学号在客户端经过去空格和格式校验后转换为 `${studentNumber}@accounts.wenyuan.invalid`，仅作为 Supabase Auth 的内部邮箱标识。Supabase 项目需要关闭邮件确认；该标识不写入公开资料表，也不在任何公开页面展示。

密码只交给 Supabase Auth。应用不自行保存、查询或比较密码。会话由 Supabase Auth 持久化，退出后清除本地会话。

### 4.5 写作台

写作台为独立视图，包含标题、分类、摘要和正文。界面突出正文编辑，不显示社区信息流。未发布内容自动保存到浏览器本地草稿；发布前展示字数、必填项和公开范围说明。

发布成功后进入作品阅读页。网络失败时保留草稿并提供明确的重试入口。

### 4.6 作者主页

作者页只展示笔名、简介、加入时间、作品数量、获赞数量和公开作品。学号及任何由学号推导出的信息均不展示。

作者本人可以编辑笔名和简介；管理员标识以小号文字呈现，不使用夸张徽章。

### 4.7 评论与回复

登录用户可以评论和回复。评论以 `parent_id` 建立树关系，界面在深度超过两级后改为缩进受限的连续讨论，避免移动端过窄。

评论作者可删除自己的评论，管理员可删除任意评论。删除父评论时保留讨论结构并显示“该评论已由作者删除”，不级联删除他人回复。

### 4.8 征稿与页脚

征稿页提供投稿范围、内容规范、社区礼仪和处理方式。页脚提供文学社说明、项目仓库入口、隐私说明与安全联系信息。

## 5. 技术架构

项目使用：

- HTML5 语义化结构。
- 独立 CSS 文件和响应式设计。
- 原生 ES Modules。
- Supabase JavaScript SDK v2。
- Supabase Auth、Postgres 和 Row Level Security。
- Node.js 内置测试运行器进行纯函数单元测试。
- Python Playwright 进行浏览器端关键路径、桌面端和移动端验证。

文件职责：

- `index.html`：应用外壳、语义结构和模块入口。
- `assets/styles.css`：视觉令牌、布局、组件和响应式规则。
- `js/app.js`：路由、状态、渲染和交互编排。
- `js/data-service.mjs`：Supabase 与演示模式的数据访问适配器。
- `js/utils.mjs`：格式化、校验、摘要、评论树和安全文本工具。
- `js/config.example.mjs`：公开配置示例，只包含 URL 和 `anon` 密钥占位符。
- `supabase/schema.sql`：表、索引、触发器、约束和 RLS 策略。
- `tests/`：单元测试与浏览器测试。
- `README.md`：本地预览、Supabase 配置、测试、GitHub Pages 和上线安全说明。

未配置 Supabase 时，应用进入明确标注的演示模式，使用内置示例数据支持界面预览与自动化测试。配置新 Supabase 项目的 URL 和 `anon` 密钥后，应用使用真实后端。演示模式不会伪装为线上数据。

## 6. 数据设计

### 6.1 `profiles`

- `id uuid primary key references auth.users(id)`
- `pen_name text`
- `bio text`
- `role text check (role in ('member', 'admin'))`
- `created_at timestamptz`
- `updated_at timestamptz`

公开查询只返回上述文学社区资料，不包含学号、邮箱或登录标识。普通用户只能更新自己的笔名和简介，不能修改角色。

### 6.2 `works`

- `id uuid primary key`
- `author_id uuid references profiles(id)`
- `title text`
- `excerpt text`
- `content text`
- `category text`
- `status text check (status in ('published', 'hidden'))`
- `is_featured boolean`
- `created_at timestamptz`
- `updated_at timestamptz`

所有人可读取已发布作品。登录用户可创建作品；作者可更新或删除自己的作品；管理员可管理全部作品和推荐状态。

### 6.3 `likes`

- `work_id uuid references works(id)`
- `user_id uuid references profiles(id)`
- `created_at timestamptz`
- 复合主键 `(work_id, user_id)`

所有人可读取计数。登录用户只能新增和删除自己的点赞。

### 6.4 `comments`

- `id uuid primary key`
- `work_id uuid references works(id)`
- `user_id uuid references profiles(id)`
- `parent_id uuid references comments(id)`
- `content text`
- `is_deleted boolean`
- `created_at timestamptz`
- `updated_at timestamptz`

所有人可读取公开作品下的评论。登录用户可创建评论，只能软删除自己的评论；管理员可软删除任意评论。

### 6.5 `site_settings`

- `key text primary key`
- `value jsonb`
- `updated_at timestamptz`

所有人可读取公开站点设置。只有管理员可修改编辑部短消息、征稿说明和社区规则。

## 7. 数据流与权限

注册时，前端校验学号格式、密码强度和笔名，再将学号转换为内部 Auth 标识并调用 Supabase Auth。数据库触发器为新账户创建 `profiles` 行。学号不复制到业务表。

登录后，应用读取 Auth 会话与对应 `profiles`。所有写操作依赖 `auth.uid()` 的 RLS 判断。前端权限只用于改善界面，数据库策略是最终权限边界。

点赞采用乐观更新；请求失败时回滚界面数字与选中状态。作品发布、资料修改、评论和删除等待数据库确认后再提示成功。

## 8. 错误处理与安全

- 所有用户输入通过 DOM `textContent` 或等效安全方式渲染，不拼接未转义 HTML。
- 标题、摘要、正文、笔名、简介和评论在前端与数据库约束中同时限制长度。
- 加载失败显示原因、保留当前位置并提供重试，不使用模糊的“操作失败”作为唯一提示。
- 删除操作使用可访问的确认弹窗。
- 未登录用户触发写作、点赞或评论时打开登录弹窗，并在登录后返回原操作位置。
- 前端只允许出现 Supabase 项目 URL 与 `anon` 密钥；`service_role`、数据库密码和其他服务端密钥不得进入仓库。
- 正式上线必须在 Supabase SQL Editor 中执行并验证 `schema.sql` 的 RLS 策略。
- 学号映射登录适用于社内平台原型和受控上线；需要密码找回或真实学生身份验证时，应绑定并验证学校邮箱，或增加受保护的 Supabase Edge Function。

## 9. 响应式与可访问性

桌面端验证宽度为 1440×1000，移动端验证宽度为 390×844，并补充 768 像素平板断点检查。移动端导航、筛选和社区侧栏转换为顺序内容，不发生横向滚动。

所有交互元素支持键盘操作和清晰焦点样式。模态弹窗管理焦点、支持 Escape 关闭并恢复触发按钮焦点。正文颜色对比、按钮状态和输入错误不只依赖颜色表达。

## 10. 测试与验收

自动化测试覆盖：

- 学号、密码、笔名和作品字段校验。
- 日期、摘要、字数与评论树构建。
- 搜索、分类和排序。
- 哈希路由解析。
- 演示模式下的发布、删除、点赞、取消点赞、评论、回复与软删除。
- 登录注册弹窗、写作台、阅读页、作者页和征稿页导航。
- 普通成员和管理员的权限入口。
- 桌面端与移动端关键页面截图、溢出检查和浏览器控制台错误检查。

验收标准：

1. 首页不展开全文，不出现刊期或封面结构。
2. 视觉符合米白、墨黑、朱砂、宋体、细线和大量留白的文学社区方向。
3. 所有要求的社交与内容功能在演示模式可运行。
4. 配置 Supabase 后使用 Auth 和 RLS，不查询或存储明文密码。
5. 任何公开页面均不展示学号。
6. 单元测试和浏览器测试通过。
7. 1440×1000 与 390×844 页面无横向溢出，主要交互可用。
8. README 给出本地预览、数据库初始化、测试、GitHub 上传、Pages 发布和正式上线安全清单。
