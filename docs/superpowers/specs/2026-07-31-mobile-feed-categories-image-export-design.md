# 文苑移动作品流、分类与图片导出设计

日期：2026-07-31

## 1. 目标

在不破坏现有登录、投稿、点赞、评论、回复、作者主页和管理员权限的前提下，完成以下改版：

1. 将“诗歌”细分为“新诗”和“旧诗”，投稿时不再显示“诗歌”。
2. 现有 `category = '诗歌'` 的作品统一迁移为“新诗”。
3. 移动端首页改为沉浸式横向文笺作品流；推荐优先，其后随机且单次会话内尽量不重复。
4. 点击作品卡片进入完整阅读页，并在同一页面继续点赞和讨论。
5. 个人主页只允许修改简介，不再提供笔名修改入口。
6. 阅读页可直接生成并导出作品图片；采用已确认的 A“素笺”模板和透明“学生文学社”书法字样。

## 2. 不在本次范围内

- 不增加笔名修改冷却期；笔名编辑功能已取消。
- 不建设服务端图片渲染服务。
- 不改变 Supabase Auth 登录方式、用户标识或管理员判定方式。
- 不重做桌面端整体信息架构；桌面端只做分类、简介表单和导出入口所需调整。

## 3. 分类与数据兼容

前端统一分类顺序：

`全部、新诗、旧诗、散文、小说、随笔、其他`

其中“全部”只用于筛选，不写入数据库。投稿下拉框只显示：

`新诗、旧诗、散文、小说、随笔、其他`

数据库迁移使用单个事务：

1. 删除现有 `works_category_check` 约束。
2. 将所有 `category = '诗歌'` 的行更新为 `category = '新诗'`。
3. 添加只允许新分类集合的约束。

迁移脚本必须可重复运行：先检查并删除旧约束，更新语句天然幂等，再重新添加目标约束。

演示数据和测试数据中的“诗歌”同步替换为“新诗”。诗歌排版判断同时支持“新诗”和“旧诗”，两者都保留作者输入的单次换行，不使用首字放大或首行缩进。

## 4. 移动端首页

### 4.1 布局

宽度小于或等于 760px 时，首页进入移动作品流模式：

- 顶部保留品牌、账户入口和横向分类筛选。
- 主体每次聚焦一张文笺作品卡。
- 底部保留“翻阅、讨论、写作、我的”四个主要入口。
- 不在卡片中展开长篇全文。

桌面端继续使用现有首页布局。

### 4.2 卡片内容

- 新诗、旧诗：短诗可在卡片中完整展示；长诗显示保持分行的节选。
- 散文、小说、随笔、其他：显示标题、作者、分类、摘要和互动数量。
- 点击卡片进入 `#/works/:id` 阅读页。
- 卡片内操作区保留喜欢数、评论数和导出入口；触摸滑动不能误触打开作品。

### 4.3 滑动规则

- 手指向左滑：显示下一篇新作品。
- 手指向右滑：返回本次会话中已经看过的上一篇。
- 水平移动超过 56px 且明显大于垂直移动时才触发翻页。
- 短距离拖动恢复原位。
- 切换分类或搜索条件时重建作品队列。

### 4.4 推荐优先、随后随机

前端为当前筛选结果建立会话队列：

1. `is_featured = true` 的推荐作品先按 `created_at` 降序排列。
2. 其余作品使用每次会话生成的随机种子洗牌。
3. 已在当前会话展示的作品不再次加入队列，直到当前集合全部看完。
4. 无推荐标记或字段时，全部作品进入随机部分。
5. 队列耗尽后提示“本次已经读完”，用户可点击“重新翻阅”生成新顺序。

现有数据库若没有 `is_featured` 字段，本轮增加布尔字段，默认 `false`；管理员可在 Supabase 表格或后续管理入口设置推荐。

## 5. 阅读与讨论

作品卡片点击后打开现有独立阅读页：

- 显示完整标题、作者、分类、日期和正文。
- 新诗、旧诗严格保留逐行和分节。
- 散文、小说、随笔按段落排版。
- 保留喜欢/取消喜欢、评论、回复、删除评论和管理员删除作品能力。
- 增加“生成作品图片”按钮。

移动端把阅读正文放在互动操作之前，评论区放在正文之后，避免讨论打断阅读。

## 6. 个人主页

- 自己的作者主页仍显示笔名，但笔名为只读文本。
- 编辑表单只保留“个人简介”文本域和“保存简介”按钮。
- 前端 `updateProfile` 接口只接受并提交 `bio`。
- Supabase 权限改为只授予普通登录用户更新 `bio` 和 `updated_at`，不再授予 `pen_name` 列更新权限。
- 注册时仍要求填写初始笔名；注册完成后普通用户不能从网站修改。

## 7. 作品图片导出

### 7.1 模板

采用 A“素笺”：

- 米白纸张背景和极细边框。
- 图片顶部直接显示加粗作品标题，不显示“新诗 · 文苑”等分类抬头。
- 正文保留作品真实排版。
- 作者和日期放在底部左侧。
- 透明“学生文学社”书法字样放在右下角，宽度约为画面宽度的 30%，不得覆盖正文。
- 字样资源路径：`assets/student-literature-society-wordmark.png`。

### 7.2 尺寸与分页

- 输出格式：PNG。
- 固定宽度：1080px。
- 单页目标尺寸：1080 × 1920px，适合手机直接查看。
- 短作品只生成一页。
- 长作品按可用正文高度分页；诗歌按完整行分页，散文/小说按段落和换行分页。
- 多页文件名使用 `作品标题-作者-01.png`、`作品标题-作者-02.png`。
- 每页都带页码、作者信息和右下角文学社字样。

### 7.3 生成与保存

采用纯前端离屏 DOM 模板生成：

1. 根据作品类型将正文拆成不可破坏的排版单元。
2. 在不可见的 1080px 宽导出容器中逐单元测量并分页。
3. 将每页 DOM 转为 PNG Blob。
4. 单页作品直接下载；多页作品提供“全部下载”。
5. 支持 Web Share 文件分享的移动浏览器优先打开系统分享面板；否则下载 PNG。

生成过程只在本地浏览器发生，不把作品内容上传到第三方图片服务。透明字样使用项目本地资源，等待字体和图片加载完成后再开始渲染。

## 8. 错误处理

- 没有作品时显示空状态，不创建滑动队列。
- 导出过程中禁用按钮并显示“正在生成”。
- 图片或字体加载失败时显示可理解的错误提示并允许重试。
- 移动浏览器阻止多文件下载时，显示逐页下载按钮。
- 分享 API 不支持文件时自动回退下载，不显示技术错误。
- Supabase 迁移尚未执行而旧数据仍含“诗歌”时，前端将其临时视为“新诗”，避免阅读排版失效；正式发布前仍必须执行迁移。

## 9. 测试与验收

### 自动化

- 分类常量不再包含“诗歌”，投稿默认值为“新诗”。
- 新诗和旧诗都采用诗歌分行渲染。
- 旧“诗歌”数据在兼容层被映射为“新诗”。
- 推荐作品排在随机作品之前，同一队列不重复。
- 向左/向右滑动分别前进和返回，短距离拖动不切换。
- 个人资料更新只提交 `bio`。
- Supabase schema 含新分类约束、推荐字段和只读笔名权限。
- 导出分页不拆诗行，文件名和页码正确。

### 浏览器验证

桌面端：

- 首页、筛选、投稿、阅读、作者主页和评论功能无回归。
- 阅读页可生成并下载图片。

移动端（390 × 844）：

- 首页只聚焦一张作品卡，分类可横向滚动。
- 左滑下一篇、右滑上一篇、点击进入阅读页。
- 阅读页诗歌逐句分行。
- 导出预览为 1080 × 1920 比例，字样透明且不挡正文。
- 长作品分页并可逐页保存。

## 10. 发布顺序

1. 在本地完成代码和测试。
2. 运行 Supabase 分类与权限迁移。
3. 再推送 GitHub Pages 前端。
4. 验证线上注册、投稿新诗/旧诗、阅读、评论和导出。

数据库迁移与前端发布必须在同一维护窗口完成，避免旧约束拒绝“新诗/旧诗”投稿。
